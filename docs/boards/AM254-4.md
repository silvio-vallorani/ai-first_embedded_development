# AM254-4 custom board

The AM254-4 (AM Microsystems, EtherCAT load-cell converter; KiCad project AM254-4, schematic title block rev 3, 2025-11-28) is the **target board** of this project and the **sacrificial board** for every irreversible operation: production-style keys, encrypted images, fuse programming, lifecycle changes (OEM Closed) and authenticated debug.

The hardware design files are private and are never committed (`hw_reference/` is in `.gitignore`). This page records what the firmware needs from them, by reference designator and MCU ball. The machine-readable summary is `boards/am254-4/board.yml`.

## Schematic review against the MIMXRT1180-EVK (2026-11-09)

Reviewed from the KiCad project (schematic and PCB). The first board used was an AM254-5; it turned out not to work and was replaced on 2026-11-09 by a working AM254-4 (fully erased before use). The AM254-4 schematic was compared with the AM254-5 one: every MCU pin the firmware depends on (FlexSPI1 port A, LEDs, J1 SWD/UART, boot mode, crystals, supplies, GPIO_AD_27 = ADC_MCLK) is identical. Differences between the two revisions:

| Item | AM254-5 | AM254-4 | Firmware impact |
|---|---|---|---|
| R95 (DL1 series resistor) | 1 kΩ | 3.3 kΩ | DL1 is dimmer (about 0.4 mA) |
| U5 | LT6202 op-amp | NCP163 2.5-V LDO, EN = GPIO_EMC_B1_09 (ENABLE_2.5VS), 100 kΩ pull-down R61 | The 2.5-V sensor rail stays off unless firmware drives GPIO_EMC_B1_09 high; the LED example does not use it |
| GPIO_AON_18 (FLEX.SPI2.MOSI) | not connected | to U11 (AD7767) pin 15 | None until the ADC is used |
| Other | — | C47 1 µF, R104/R109/R110 0 Ω added, R7/R9/R10/R11/C119 removed, DL1 part 150040GS73220 | None |

### Serial NOR flash: same as the EVK

| Signal | MCU pad (ball) | AM254-4 (U8, W25Q128JWSIQ) | EVK |
|---|---|---|---|
| FLEXSPI1_A_SCLK | GPIO_B2_08 (A7) | SCK | same |
| FLEXSPI1_A_SS0_B | GPIO_B2_09 (D10) | CS#, 4.7 kΩ pull-up R69 to +1.8 V | same |
| FLEXSPI1_A_DATA00..03 | GPIO_B2_10..13 (A10, B9, A8, B8) | IO0, IO1, IO2/WP#, IO3/RESET# | same |
| FLEXSPI1_A_DQS | GPIO_B2_07 (A6) | test point TP24 only | read-strobe loopback |
| Supply | NVCC_GPIO1/2 = +1.8 V | VCC +1.8 V | 1.8 V |

- **Device and port match the EVK.** The device is the same 128-Mbit 1.8-V W25Q128JW, on the same FlexSPI1 port A, 4-bit.
- **The EVK boot configuration fits unchanged.** The SDK's FlexSPI configuration block (133 MHz, sampling clock looped back from the DQS pad, 16 MiB) applies as it is. The bootloader, the flash layout (`MEMORY_MAP.md`) and the log region need no change.
- **One flash device instead of two.** U13 (W25Q128JWPIQ, WSON-8) is a second footprint for the same signals, marked not fitted. The EVK has two flash devices (port A and port B); the project layout already uses one 16-MiB device only.

## Findings

| # | Severity | Finding | Consequence |
|---|---|---|---|
| F1 | **High (firmware)** | GPIO_AD_27, the EVK user-LED pad, is **ADC_MCLK** to the AD7767 (U11) on the AM254-4 | The EVK firmware would toggle the ADC master clock. The AM254-4 build uses its own CM7 pin mux and never touches GPIO_AD_27; never flash an EVK image on this board |
| F2 | Low (schematic) | DL2's symbol has its pin names swapped compared with the other LEDs (pin 1 = A on GND). The PCB connects pad 1 to GND, like DL1/DL4/DL5 | Probably cosmetic; check the fitted orientation of DL2 before relying on it |
| F3 | Info | DQS (GPIO_B2_07) goes only to TP24 | Correct for loopback sampling; keep TP24 unloaded |
| F4 | Info | ONOFF is not connected and PMIC_STBY_REQ goes only to TP1 | No effect on boot; low-power modes that rely on them are not available |
| F5 | Resolved | The SW1 setting for FlexSPI NOR boot is not marked on the schematic | Measured: SRC SBMR2 boot mode = flash boot; the board boots from the NOR as delivered |
| F6 | Fixed (2026-11-10) | Direct ROM boot (standalone image): NXP `Prepare_CM7()` hangs in its DMA4 TCM clear, because no TRDC setup has run yet (MCUboot does it before jumping to the application) | `boards/am254-4/sdk/cm33/hardware_init.c` runs NXP's MCUboot `trdc_setup()` before `Prepare_CM7()` when not under MCUboot. Verified with LED checkpoints and on power-on |
| F7 | Fixed (2026-11-10) | Standalone images: the log service's `mflash` driver reprograms the FlexSPI while running from it (standard XIP linker); assert `count <= FLEXSPI_LUT_COUNT` in `FLEXSPI_UpdateLUT()`, then bus fault | Standalone builds use NXP's bootloader XIP linker, which runs `mflash_drv.c` and `fsl_flexspi.c` from ITCM, as the MCUboot application linker does (`examples/dual_core_led_toggle/standalone/primary.cmake`, ADR-0015). Applies to both boards |
| F8 | Open | Standalone image after a debugger (warm) reset: `CM7 ready` is logged but DL1 does not toggle; after a power-on it does. The MCUboot variant toggles after both | Suspected TRDC state left by the previous run (CM7 write access to GPIO3). Watchdog/software resets are warm resets too: to be solved with the TRDC policy (CRA plan phase C) |

## Firmware support

- **`boards/am254-4/include/aied_board.h`** defines the board name and the user LED (DL1: RGPIO3, pin 9).
- **`boards/am254-4/sdk/cm7/pin_mux.c`** replaces the EVK board-port pin mux of the CM7 image and configures only GPIO_EMC_B1_41. The build selects it through `CUSTOM_PRJ_CONF_PATHS` (`pinmux_customize_folder`), so the SDK stays unmodified.
- **The rest of the SDK EVK board support is reused**, because the AM254-4 matches it: clocks, DCDC, the CM33 pin mux (debug UART only), the FlexSPI configuration block and the MCUboot bootloader (UART + FlexSPI1 port A only).
- **Direct ROM boot (standalone):** the CM33 board-port `hardware_init.c` and `app.h` replace the EVK ones (F6); standalone builds link with NXP's bootloader XIP linker (F7).
- **Build:**

  ```sh
  scripts/build_rt1180.sh --board am254-4 [--mcuboot ...]       # or build_rt1180.ps1 -Board am254-4
  .venv/bin/python scripts/rt1180_mcuboot.py --board am254-4 build
  ```

  Outputs go to `build/am254-4-led-toggle`, `build/am254-4-led-mcuboot` and `build/am254-4-update-test`. CI builds both boards.
- **Probe: SEGGER J-Link** (ADR-0017) on J1. The tools use device `MIMXRT1189xxx8_M33` with NXP's CM33 jlinkscript; LinkServer remains available (`--probe-tool linkserver`). The console needs a 3.3-V USB-UART on J1 pins 7/8.

## Rules for the sacrificial board

- **Every irreversible step is authorized one at a time.** Fuse programming, SRK hash, lifecycle change and debug-authentication provisioning are each run only after the user authorizes that exact operation, and the operation, values and outcome are recorded in this page.
- **Record the board's state before the first irreversible step.** Note the serial number or label and the fuse and lifecycle state, so later results can be traced to a known board.
- **Keep the debug credentials and any production-style keys off the repository.** That includes the SRK private keys, the DCK and the encryption keys.

## Bring-up checklist (first power-on)

1. Check the supply rails (+3.3 V, +1.8 V, VDD_SOC) without the probe connected.
2. Connect the J-Link on J1 and check that it connects to the MIMXRT1189 (J-Link Commander `connect`, device `MIMXRT1189xxx8_M33`, SWD), then the same through the J-Link MCP server.
3. Read the NOR JEDEC ID; W25Q128JW is expected.
4. Flash `scripts/rt1180_mcuboot.py --board am254-4 flash initial` and check the console and DL1 (MCUBOOT_UPDATE_TEST T1).
5. Continue with T2–T4, then the `logerase` check, then the ADR-0016 spikes.
