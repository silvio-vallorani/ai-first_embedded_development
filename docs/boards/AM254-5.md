# AM254-5 custom board

The AM254-5 (AM Microsystems, EtherCAT load-cell converter, schematic rev 5, 2026-01-27) is the **target board** of this project and the **sacrificial board** for every irreversible operation: production-style keys, encrypted images, fuse programming, lifecycle changes (OEM Closed) and authenticated debug.

The hardware design files are private and are never committed (`hw_reference/` is in `.gitignore`). This page records what the firmware needs from them, by reference designator and MCU ball. The machine-readable summary is `boards/am254-5/board.yml`.

## Schematic review against the MIMXRT1180-EVK (2026-11-09)

Reviewed from the KiCad project (schematic and PCB) of rev 5. The board has not been powered with this firmware yet.

### Serial NOR flash: same as the EVK

| Signal | MCU pad (ball) | AM254-5 (U8, W25Q128JWSIQ) | EVK |
|---|---|---|---|
| FLEXSPI1_A_SCLK | GPIO_B2_08 (A7) | SCK | same |
| FLEXSPI1_A_SS0_B | GPIO_B2_09 (D10) | CS#, 4.7 kΩ pull-up R69 to +1.8 V | same |
| FLEXSPI1_A_DATA00..03 | GPIO_B2_10..13 (A10, B9, A8, B8) | IO0, IO1, IO2/WP#, IO3/RESET# | same |
| FLEXSPI1_A_DQS | GPIO_B2_07 (A6) | test point TP24 only | read-strobe loopback |
| Supply | NVCC_GPIO1/2 = +1.8 V | VCC +1.8 V | 1.8 V |

- **Device and port match the EVK.** The device is the same 128-Mbit 1.8-V W25Q128JW, on the same FlexSPI1 port A, 4-bit.
- **The EVK boot configuration fits unchanged.** The SDK's FlexSPI configuration block (133 MHz, sampling clock looped back from the DQS pad, 16 MiB) applies as it is. The bootloader, the flash layout (`MEMORY_MAP.md`) and the log region need no change.
- **One flash device instead of two.** U13 (W25Q128JWPIQ, WSON-8) is a second footprint for the same signals, marked not fitted. The EVK has two flash devices (port A and port B); the project layout already uses one 16-MiB device only.

## Findings

| # | Severity | Finding | Consequence |
|---|---|---|---|
| F1 | **High (firmware)** | GPIO_AD_27, the EVK user-LED pad, is **ADC_MCLK** to the AD7767 (U11) on the AM254-5 | The EVK firmware would toggle the ADC master clock. The AM254-5 build uses its own CM7 pin mux and never touches GPIO_AD_27; never flash an EVK image on this board |
| F2 | Low (schematic) | DL2's symbol has its pin names swapped compared with the other LEDs (pin 1 = A on GND). The PCB connects pad 1 to GND, like DL1/DL4/DL5 | Probably cosmetic; check the fitted orientation of DL2 before relying on it |
| F3 | Info | DQS (GPIO_B2_07) goes only to TP24 | Correct for loopback sampling; keep TP24 unloaded |
| F4 | Info | ONOFF is not connected and PMIC_STBY_REQ goes only to TP1 | No effect on boot; low-power modes that rely on them are not available |
| F5 | To check | The SW1 setting for FlexSPI NOR boot is not marked on the schematic | Confirm the switch positions against the RT1180 reference manual boot-mode table before the first boot |

## Firmware support

- **`boards/am254-5/include/aied_board.h`** defines the board name and the user LED (DL1: RGPIO3, pin 9).
- **`boards/am254-5/sdk/cm7/pin_mux.c`** replaces the EVK board-port pin mux of the CM7 image and configures only GPIO_EMC_B1_41. The build selects it through `CUSTOM_PRJ_CONF_PATHS` (`pinmux_customize_folder`), so the SDK stays unmodified.
- **The rest of the SDK EVK board support is reused**, because the AM254-5 matches it: clocks, DCDC, the CM33 pin mux (debug UART only), the FlexSPI configuration block and the MCUboot bootloader (UART + FlexSPI1 port A only).
- **Build:**

  ```sh
  scripts/build_rt1180.sh --board am254-5 [--mcuboot ...]       # or build_rt1180.ps1 -Board am254-5
  .venv/bin/python scripts/rt1180_mcuboot.py --board am254-5 build
  ```

  Outputs go to `build/am254-5-led-toggle`, `build/am254-5-led-mcuboot` and `build/am254-5-update-test`. CI builds both boards.
- **LinkServer** uses the EVK device configuration (`MIMXRT1189:MIMXRT1180-EVK`) for both boards, since the NOR is identical. `LINKSERVER_DEVICE` overrides it if a custom configuration is needed.

## Rules for the sacrificial board

- **Every irreversible step is authorized one at a time.** Fuse programming, SRK hash, lifecycle change and debug-authentication provisioning are each run only after the user authorizes that exact operation, and the operation, values and outcome are recorded in this page.
- **Record the board's state before the first irreversible step.** Note the serial number or label and the fuse and lifecycle state, so later results can be traced to a known board.
- **Keep the debug credentials and any production-style keys off the repository.** That includes the SRK private keys, the DCK and the encryption keys.

## Bring-up checklist (first power-on)

1. Check the supply rails (+3.3 V, +1.8 V, VDD_SOC) without the probe connected.
2. Connect the probe on J1 and check that LinkServer sees the MIMXRT1189 (`LinkServer probes`, then a connect).
3. Read the NOR JEDEC ID; W25Q128JW is expected.
4. Flash `scripts/rt1180_mcuboot.py --board am254-5 flash initial` and check the console and DL1 (MCUBOOT_UPDATE_TEST T1).
5. Continue with T2–T4, then the `logerase` check, then the ADR-0016 spikes.
